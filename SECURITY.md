# Security Policy

## Supported versions

Security fixes are applied to the latest release. Reproduce issues with the newest release before reporting them.

## Reporting a vulnerability

Do not disclose exploitable details in a public issue. Use GitHub's **Report a vulnerability** button on the repository's Security tab if private reporting has been enabled; otherwise, use a trusted private contact with the repository owner before public disclosure.

Include the impact, a minimal reproduction, affected versions, environment details, known workarounds, and whether the issue is already public or actively exploited.

Maintainers should acknowledge a complete report within seven days, communicate during assessment, and coordinate disclosure after a fix is available. These are response goals, not a service-level guarantee.

Security-relevant areas include preset parsing, path validation, browser/server API boundaries, unintended writes, and ComfyUI integration risks. Ordinary compatibility bugs belong in a normal public issue unless they create a security impact.
